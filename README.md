# pollux-plf-cicd-fixture

CI/CD 사슬을 재는 **카나리아**다. 제품이 아니다.

## 왜 있나

사슬(변경 감지 → 빌드 → Nexus 적재 → 채널 승격 → 보존)이 도는지 재려면 통과시킬 무언가가
필요하다. 실물 repo 로 재면 **진짜 패키지가 잘못 승격되거나 지워질 수 있다.**

## 왜 한 repo 에 두 형식인가

**형식이 둘인 이유**는 우연 일치 방어다 — 하나만 되면 그게 사슬 덕인지 그 형식 덕인지 못 가른다.

**그런데 repo 는 하나다.** 우리 실물이 그 형상이기 때문이다:

```
plf-sot profiles/lib.multi-lang-library.json
  "pypi·npm·maven 셋으로 발행한다. 발행 축이 셋이라 워크플로가 더 붙는다."
```

`pollux-lib` 같은 실물은 **한 repo 가 여러 형식으로 발행**한다. 픽스처를 repo 둘로 나누면
카나리아가 실물을 안 닮게 되고, 그러면 카나리아 통과가 실물 통과를 덜 보장한다.
형식이 늘면 **디렉터리가 는다** — 실물이 그러하듯.

## 성질

- **기능이 없다.** 있으면 사슬 실패 때 "사슬 문제인가 기능 문제인가" 를 못 가른다.
- **버전만 올린다.** 적재된 것이 방금 빌드한 것인지 그 값으로 확인한다.
  `VERSION` 이 정본이고 각 형식 매니페스트가 그 값을 따른다 — 두 산출물이 **같은 커밋에서
  나왔다는 대조**가 가능해진다.
- **영구다.** PoC 산출물로 시작하지만, 사슬이 바뀔 때마다(엔진 교체·채널 추가·새 사이트 기립)
  같은 자로 재려면 계속 있어야 한다. 지우는 시점은 CI/CD 자체를 걷을 때다.

## 구조

```
VERSION                  정본 버전 — 두 형식이 이 값을 따른다
pypi/                    python-wheel 축
npm/                     npm-package 축
```

## 쓰는 법

이 repo 를 직접 부르지 않는다. **사이트 실행기가 등록부에서 파생해** 당겨간다.
`VERSION` 을 올리는 커밋이 곧 사슬의 방아쇠다.
